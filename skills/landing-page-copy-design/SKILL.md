# Landing Page Copy Design

Build landing pages around belief change, not around feature inventory.

## Core insight

A landing page converts when it moves the visitor from "this is not for me" to "this understands my problem and offers a believable next step." The structure should follow that belief journey.

## Operating loop

1. Identify the visitor's stage: unaware, problem-aware, solution-aware, product-aware, or ready to buy.
2. Write the belief chain: current pain -> failed alternatives -> new mechanism -> proof -> low-risk next step.
3. Build the page from sections that each answer one objection.
4. Put the clearest promise above the fold: audience, outcome, mechanism, proof, CTA.
5. Add proof close to claims: screenshots, numbers, examples, testimonials, logos, demos, or concrete workflows.
6. Remove sections that do not advance belief, trust, or action.

## Page architecture

- Hero: who it is for, outcome, mechanism, CTA.
- Problem: name the painful status quo in the user's language.
- New mechanism: why this approach works when others do not.
- Product proof: show the thing, not just describe it.
- Use cases: map product to real situations.
- Objections: pricing, time, switching, trust, risk, complexity.
- CTA: one primary action, repeated after proof.

## Output format

```markdown
## Hero
Headline:
Subheadline:
Primary CTA:
Secondary CTA:

## Page Sections
1. [Section name]
   - Purpose:
   - Copy:
   - Proof needed:

## Objections handled
- Objection -> section/copy
```

## Quality bar

- The hero is understandable without scrolling.
- Claims have nearby proof.
- The CTA matches the user's readiness level.

## Anti-patterns

- Starting with "All-in-one platform" before naming the pain.
- Listing features with no narrative.
- Using testimonials as decoration instead of proof for specific claims.
