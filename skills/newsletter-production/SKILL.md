# Newsletter Production

Make each issue earn its place in the inbox.

## Core insight

A newsletter is not an update dump. It needs an editorial promise: after reading this, the audience is smarter, faster, reassured, or closer to a goal.

## Operating loop

1. Define audience, issue promise, cadence, and desired reader action.
2. Pick one theme that organizes the issue.
3. Sort inputs into must-read, useful context, proof, community, product update, and CTA.
4. Write the top section as a strong editorial lead, not an apology for emailing.
5. Keep sections modular: headline, one-sentence value, detail, link/action.
6. Write 5 subject lines with different angles: benefit, curiosity, specificity, urgency, and community.
7. Add a closing CTA and reason to reply.

## Section rules

- Put the strongest item first.
- Cut anything that only serves the sender.
- If a section has no reader benefit, remove or rewrite it.
- Use links as optional depth, not required context.

## Output format

```markdown
Subject options:
1.

Preview text:

# [Issue title]

[Lead]

## Section
- Why it matters:
- Details:
- CTA/link:
```

## Quality bar

- The issue has one clear editorial spine.
- Subject line is compelling but honest.
- Reader value appears before company value.

## Anti-patterns

- Beginning with "Hope you're well" or internal housekeeping.
- Sending five unrelated announcements as one issue.
- Using clickbait the body does not satisfy.
