# OKR Planning Review

Make goals measurable without turning them into task lists.

## Core insight

Objectives create direction; key results create evidence. Initiatives are bets. If those three are mixed together, teams confuse activity for progress.

## Operating loop

1. Clarify strategy, team scope, time period, baseline, constraints, and decision rights.
2. Write objectives as qualitative outcomes that would matter if achieved.
3. Write key results with metric, baseline, target, owner, measurement source, and review cadence.
4. Attach initiatives as bets that may move KRs, not as KRs themselves.
5. Check for too many goals, vanity metrics, unowned dependencies, and impossible measurement.
6. Define confidence, risks, and tradeoffs.
7. Create weekly review format with status, evidence, blockers, and changes.

## OKR tests

- If completion is binary, it is probably an initiative, not a KR.
- If nobody can measure it weekly or monthly, it is not operational yet.
- If every team owns everything, no one owns the outcome.
- If success requires another team, name the dependency.

## Output format

```markdown
## Objective

### Key results
| KR | Baseline | Target | Owner | Source | Cadence |
|---|---|---|---|---|---|

### Initiatives
| Initiative | KR supported | Confidence | Risk |
|---|---|---|---|
```

## Quality bar

- KRs are outcomes, not tasks.
- Metrics have baselines and sources.
- Initiatives connect to KRs.

## Anti-patterns

- Using OKRs as a project checklist.
- Setting targets without baselines.
- Creating more goals than the team can remember.
